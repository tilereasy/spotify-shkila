# Shkila - Замена встроенного Spotify DJ

Шкила заменяет отдельные англоязычные реплики Spotify DJ локально созданной кастомной озвучкой. Расширение [Spicetify](https://spicetify.app/) читает реплики из очереди Spotify, отправляет их в локальный сервис, а сервис переводит текст через OpenAI-совместимый API и синтезирует речь с помощью OmniVoice.

Проект находится в стадии прототипа. Текущие инструкции рассчитаны на Linux и GPU NVIDIA: установочный скрипт использует путь Spicetify для Linux, а Docker Compose запрашивает GPU NVIDIA. Также нужны доступ к Spotify DJ и установленный Spicetify.

## Как это работает

1. Расширение находит в очереди Spotify DJ реплики `intro`, `jump` и `outro` и отправляет их на предварительную обработку.
2. Сервис переводит выбранные типы реплик с помощью LLM (возможна стилистическая обработка!) и сохраняет сгенерированный WAV в `cache/audio/`.
3. Когда реплика начинается, расширение запрашивает готовый WAV, приостанавливает Spotify и воспроизводит локальную запись. После неё воспроизведение продолжается.

Если перевод или аудио ещё не готовы, расширение возобновляет обычное воспроизведение Spotify DJ. По умолчанию в `config.example.yaml` для обработки выбраны `intro` и `outro`; `jump` можно добавить в `translation.prefetch_kinds`.

По поводу `jump` - он воспроизводится, когда вы решили нажать на кнопку диджея, чтобы он поменял сет треков. Не рекомендую вам ставить его обработку в конфиге, особенно если у вас сторонний провайдер, берущий плату.

## Быстрый запуск

### Требования

- Spotify с доступом к DJ и установленный [Spicetify](https://spicetify.app);
- Docker Compose с доступом к GPU NVIDIA;
- ключ провайдера с OpenAI-совместимым API для перевода (для локального API без авторизации - непустое значение);
- для режима `clone` - образец голоса в формате WAV.

### 1. Настройте конфигурацию

```bash
git clone https://github.com/tilereasy/spotify-shkila.git
cd spotify-shkila
cp config.example.yaml config.yaml
mkdir -p voices cache/audio
```

В `config.yaml` нужно указать полный URL API со схемой (`https://.../v1`), имя модели и целевой язык перевода, например `Russian` или `English` or `Spanish`. Стиль перевода можно оставить пустым. В секции `voice` выберите один из режимов:

- `clone` - укажите путь к образцу в `voice.clone.ref_audio` (по умолчанию `./voices/reference.wav`);
- `design` - опишите желаемый голос в `voice.design.instruct`.

**(я рекомендую именно clone - он работает лучше)**

Пример рассчитан на русский язык синтеза (`tts.language: ru`) и устройство `cuda:0`. При необходимости согласуйте язык перевода и синтеза. Файл `config.yaml` исключён из Git.

### 2. Запустите сервис

```bash
export DJ_LLM_API_KEY='ваш-ключ'
docker compose up --build -d
curl http://127.0.0.1:8765/health
```

При работе с локальной моделью без авторизации всё равно задайте непустое значение ключа, например `DJ_LLM_API_KEY=local`: текущий код проверяет наличие ключа при запуске. Для API, работающего на хосте, можно использовать адрес вида `http://host.docker.internal:PORT/v1` в `llm.base_url`.

Ожидаемый ответ проверки: `{"status":"ok"}`. При первом запуске загрузка модели и подготовка голоса могут занять время. Сервис слушает порт `8765` только на `127.0.0.1` хоста.

**Моя рекомендация: открывайте Spotify только после полного запуска сервиса. Расширение отправляет найденные в очереди реплики при первом обнаружении и не повторяет отправку того же ключа, если сервис в тот момент был недоступен. Иначе часть реплик останется без локальной озвучки до обновления очереди или перезапуска расширения.**

### 3. Установите расширение

```bash
bash scripts/install-extension.sh
```

Скрипт копирует расширение в `~/.config/spicetify/Extensions/`, добавляет его в конфигурацию Spicetify и выполняет `spicetify apply`. После установки откройте Spotify DJ. События расширения видны в консоли Spotify, обработка - в `docker compose logs -f shkila-backend`.

## Настройки

| Секция | Назначение |
| --- | --- |
| `llm` | URL, ключ, модель и параметры OpenAI-совместимого API |
| `translation` | Целевой язык, стиль реплик и типы для предварительной обработки |
| `tts` | Модель OmniVoice, устройство, язык и параметры синтеза |
| `voice` | Режим `clone` или `design` и соответствующие настройки голоса |

Ключ передаётся через переменную окружения `DJ_LLM_API_KEY`: значение `${DJ_LLM_API_KEY}` в YAML подставляется при загрузке конфигурации.

## Локальный API

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка работы сервиса |
| `POST /events` | Приём событий `prefetch` и `start` от расширения |
| `GET /narrations` | Список реплик и их статусов |
| `GET /narrations/{key}` | Данные одной реплики |
| `GET /narrations/{key}/audio` | Готовый WAV; `409`, если обработка ещё не закончена |

Статусы реплики: `pending`, `translating`, `synthesizing`, `ready`, `failed`.

**Docker Compose публикует сервис только на `127.0.0.1` хоста.** API доступен локально и не открывается в домашнюю сеть через этот порт.

## Текущие ограничения

- Сопоставление реплик зависит от метаданных Spotify DJ и поведения клиента Spicetify; изменения Spotify могут нарушить работу расширения.
- Очередь и сведения о репликах хранятся в памяти сервиса. WAV-файлы остаются на диске, но после перезапуска сервиса они не подхватываются автоматически. А еще аудио-файлы не удаляются автоматически, они не занимают много места, но иногда нужно чистить. Потом исправлю.
- Расширение не ждёт окончания обработки при старте реплики: если WAV пока не готов, прозвучит обычная реплика Spotify DJ. Никто же не любит сидеть в тишине.
- Сервис использует один последовательный обработчик реплик. При длинной очереди перевод и синтез могут не успеть к воспроизведению. По моему опыту OmniVoice обычно успевает подготовить WAV, но на слабой видеокарте или при включённой обработке `jump` задержки вероятнее. Еще один момент - думающая(reasoning) модель тоже может вставлять палки в колеса.
- С `outro` замена работает стабильно. С `intro` есть особенность: реплика связана с треком, поэтому обычный пропуск может перескочить и сам трек. Поэтому расширение делает скип только для `outro`, в `intro` после Шкилы звучит оригинальный DJ.

## Структура проекта

```text
app/bridge.py       FastAPI, очередь обработки и выдача аудио
app/translator.py   перевод реплик через LLM API
app/tts.py          синтез речи через OmniVoice
spicetify/          расширение Spotify
scripts/            установка расширения
config.example.yaml пример конфигурации
compose.yaml        запуск сервиса в Docker
```
